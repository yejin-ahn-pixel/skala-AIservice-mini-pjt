# 단계 7 — 동기 LLM 호출 분리와 응답시간 제한

> 변경 기록 번호: C11 · 전체 기록은 `과제1_코드변경기록.md` · 목차는 [README](README.md)

## 1. 문제 — 무엇이, 왜, 어떤 영향이 있었나
**현상**: `async` 노드 안에서 동기 함수(`route/plan/analyze`, 내부 `httpx.post`)를 그대로 호출해서, 모델 응답을 기다리는 동안 **이벤트 루프 전체가 멈춘다**. 그 사이 다른 요청(`/health` 등)도 같이 지연된다. 또 timeout이 300초(OpenAI 120초)로 하드코딩돼 있고, qwen3의 사고 과정(thinking) 토큰과 출력 길이에 제한이 없었다.
**영향**: 느린 모델 호출 하나가 서버 전체를 세운다. 모델이 멈추면 5분 뒤에야 실패한다.

## 2. 바꾼 파일과 이유
| 파일 | 변경 | 이유 |
|---|---|---|
| `agent/nodes/routing_nodes.py`, `research_nodes.py` | `await asyncio.to_thread(deps.fast_llm.route/plan/analyze, ...)` | 함수 모양은 그대로 두고 별도 스레드에서 실행 → 기다리는 동안 서버가 다른 요청 처리 |

| `tests/test_async_llm.py` | 이벤트 루프 차단 테스트 | 효과를 숫자로 확인 |

## 3. Before 코드 (개선 전 원본)

**원본 `agent/ollama_llm.py` 88~145줄 (`OllamaLLM`)**

```python
class OllamaLLM:
    def __init__(self, model: str, usd_per_1k_tokens: float):
        self.name = f"ollama:{model}"
        self.model = model
        self.usd_per_1k = usd_per_1k_tokens

    def _chat(self, system: str, user: str, schema: dict | None = None) -> tuple[str, dict]:
        payload = {
            "model": self.model,
            "messages": [{"role": "system", "content": system},
                         {"role": "user", "content": user}],
            "stream": False,
            "options": {"temperature": 0.0},
        }
        if schema is not None:
            payload["format"] = schema
        resp = httpx.post(OLLAMA_URL, json=payload, timeout=300.0)
        resp.raise_for_status()
        data = resp.json()
        content = data["message"]["content"]
        tokens = (data.get("prompt_eval_count") or 0) + (data.get("eval_count") or 0)
        usage = {"model": self.name, "tokens": tokens,
                 "usd": round(tokens / 1000 * self.usd_per_1k, 6)}
        return content, usage

    async def _chat_stream(self, system: str, user: str, on_token=None) -> tuple[str, dict]:
        """사용자 대면 텍스트(최종 답변류) 전용 — Ollama NDJSON 스트림을 토큰 단위로
        받아 on_token(조각)을 즉시 호출해 SSE로 실시간 중계할 수 있게 한다. 분류/계획
        등 JSON 스키마 출력(route/plan/analyze)은 부분 출력이 의미가 없어 그대로 _chat을
        쓴다."""
        payload = {
            "model": self.model,
            "messages": [{"role": "system", "content": system},
                         {"role": "user", "content": user}],
            "stream": True,
            "options": {"temperature": 0.0},
        }
        chunks: list[str] = []
        usage = {"model": self.name, "tokens": 0, "usd": 0.0}
        async with httpx.AsyncClient(timeout=300.0) as client:
            async with client.stream("POST", OLLAMA_URL, json=payload) as resp:
                resp.raise_for_status()
                async for line in resp.aiter_lines():
                    if not line:
                        continue
                    data = json.loads(line)
                    piece = data.get("message", {}).get("content", "")
                    if piece:
                        chunks.append(piece)
                        if on_token is not None:
                            on_token(piece)
                    if data.get("done"):
                        tokens = ((data.get("prompt_eval_count") or 0)
                                  + (data.get("eval_count") or 0))
                        usage = {"model": self.name, "tokens": tokens,
                                 "usd": round(tokens / 1000 * self.usd_per_1k, 6)}
        usage["prompt"] = f"[SYSTEM]\n{system}\n\n[USER]\n{user}"
        return "".join(chunks), usage
```

## 5. 동작 원리 — 코드 읽는 순서
- **왜 `to_thread`인가**: `route/plan/analyze`를 전부 `async`로 바꾸면 노드·가짜 모델·테스트까지 모두 바뀐다. `to_thread`는 함수를 그대로 두고 호출 위치만 바꾼다(변경 범위 최소).
- **`think:false`**: qwen3는 답을 쓰기 전 사고 과정을 생성한다. 이 토큰도 시간이 걸리지만 사용자에게는 안 보인다. 끄면 빨라지지만 **품질에 영향이 있을 수 있다**(`OLLAMA_THINK=true`로 되돌릴 수 있음).
- **`num_predict`**: 한 번에 만들 최대 토큰. 답변이 무한히 길어지는 것을 막는다.

## 9. 한계·트레이드오프
- **`think:false`의 속도·품질 영향은 Mac에서 아직 실측하지 않았다**(이 환경에 Ollama가 없음). 보고서에는 측정한 값만 쓴다.
- 스레드 방식은 동시 요청이 많으면 스레드 수가 늘어난다(1인 시연 규모에서는 문제 없음). 완전한 비동기 클라이언트(`AsyncClient`)로의 전환은 하지 않았다.
- 타임아웃 120초는 8b 모델의 최악 응답을 고려한 값이라 정상 동작 중인 느린 호출이 끊기지는 않지만, 멈춘 호출을 5분→2분으로 줄이는 정도다.
