# 단계 5 — 모듈화: graph.py를 역할별로 분리

> 변경 기록 번호: C8, C9 · 전체 기록은 `과제1_코드변경기록.md` · 목차는 [README](README.md)

## 1. 문제 — 무엇이, 왜, 어떤 영향이 있었나
**현상**: `agent/graph.py` 한 파일(원본 338줄)에 상태 정의·노드 12개·분기 함수·그래프 조립이 모두 있었다. 같은 시스템 목록 로더(`_load_known_systems`)는 `graph.py`, `ollama_llm.py`, `openai_llm.py` 3곳에 복사돼 있었다.
**영향**: 한 노드를 고칠 때 영향 범위를 파악하기 어렵고, 복사된 코드는 일부만 고쳐질 위험이 있다. 단위 테스트에서 노드를 따로 불러 쓰기도 불편하다.

## 2. 바꾼 파일과 이유
| 파일 | 변경 | 이유 |
|---|---|---|
| `agent/state.py` (신규) | `AgentState`, `_cost` | 모든 노드의 공통 상태 |
| `agent/streaming.py` (신규) | `get_writer` | 토큰 스트리밍 접근 지점을 한 곳으로 (테스트에서 쉽게 대체) |

## 4. After 코드 (현재)

**현재 `agent/graph.py` 44~76줄 (`build_graph`)**

```python
def build_graph(deps: SupervisorDeps):
    g = StateGraph(AgentState)
    # Wave 13 — 명시적 의존성 주입. [C13] 같은 주입을 하되 노드별 실행 시간도 기록한다.
    # Before: node = lambda fn: partial(fn, deps=deps)
    node = lambda fn: timed_node(fn.__name__.removesuffix("_node"), fn, deps)
    g.add_node("route", node(route_node))
    g.add_node("chat_answer", node(chat_answer_node))
    g.add_node("plan", node(plan_node))
    g.add_node("clarify", node(clarify_node))
    g.add_node("gate", node(gate_node))
    g.add_node("research", node(research_node))
    g.add_node("replan_check", node(replan_check_node))
    g.add_node("analysis", node(analysis_node))
    g.add_node("write", node(write_node))
    g.add_node("validate", node(validate_node))
    g.add_node("finalize", node(finalize_node))

    g.set_entry_point("route")
    g.add_conditional_edges("route", _after_route,
                            {"chat_answer": "chat_answer", "plan": "plan"})
    g.add_edge("chat_answer", END)
    g.add_conditional_edges("plan", _after_plan, {"clarify": "clarify", "gate": "gate"})
    g.add_edge("clarify", END)
    g.add_edge("gate", "research")
    g.add_edge("research", "replan_check")
    g.add_conditional_edges("replan_check", _after_replan_check,
                            {"analysis": "analysis", "research": "research"})
    g.add_edge("analysis", "write")
    g.add_edge("write", "validate")
    g.add_conditional_edges("validate", _after_validate,
                            {"finalize": "finalize", "write": "write"})
    g.add_edge("finalize", END)
    return g.compile()
```

## 5. 동작 원리 — 코드 읽는 순서
LangGraph는 "노드(함수)"와 "엣지(순서)"로 구성된다. 노드 구현은 `nodes/`로 옮기고, `graph.py`는 `build_graph`에서 `g.add_node(...)`·`g.add_edge(...)`로 **연결만** 한다. 노드의 동작·순서·이벤트 이름은 바꾸지 않았다(기존 테스트가 수정 없이 통과하는 것이 증거).
의존성 주입(`SupervisorDeps`)은 그대로이며, 모든 노드는 `timed_node`(C13)를 거쳐 `deps`를 받는다.
